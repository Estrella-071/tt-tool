# ADB 모바일 모드

[English](ADB.md) · [繁體中文](ADB.zh-TW.md) · [日本語](ADB.ja.md) · 한국어

Windows 컴퓨터에서 USB로 Android 휴대전화를 연결합니다. 휴대전화에 APK를 설치하거나 root를 사용할 필요는 없습니다.

## 시작하기

1. Windows x64 버전을 설치하고 [설치 안내서](INSTALLER.ko.md)에 따라 Android SDK Platform-Tools와 FFmpeg를 준비합니다.
2. 휴대전화에서 USB 디버깅을 켜고 컴퓨터를 승인한 다음 게임을 세로 방향으로 엽니다.
3. tt tool을 엽니다. 승인된 휴대전화가 한 대면 자동으로 연결됩니다. 여러 대면 기기를 선택하고 연결하세요.
4. 활동을 선택한 후 "설정"을 열고 "자동 학습" 또는 "수동 설정"을 선택한 다음 휴대폰에서 드래그 범위의 모서리와 작동 지점을 미리 봅니다. 타이밍과 대피 임계값은 슬라이더로 조정할 수 있으며 기본값을 복원할 수 있습니다. 두 모드의 설정은 별도로 저장되며, 저장 후 즉시 적용됩니다.
5. 시작하려면 "낚시 시작" 또는 스페이스 바를 누르고 일시 중지하려면 다시 누르십시오. 일시 중지 중에도 개수와 세션 시간이 유지됩니다. 세션을 종료하고 다음에 다시 계산을 시작하려면 "종료" 또는 Esc를 누르세요.

후크를 설정하거나 후크를 당긴 후에도 화면이 바뀌지 않으면 휴대폰 낚시는 화면이 안정적인지 확인한 후 자동으로 다시 시도합니다. 동일한 후크를 다시 시도하면 횟수가 반복적으로 표시되지 않습니다. 일시적으로 화면을 확인할 수 없는 경우에는 계속 관찰하고 인식이 복원된 후 계속됩니다. 후크 수의 상한을 설정하면 재시도도 작업 수의 상한에 포함됩니다. 시간 제한은 여전히 ​​유효합니다.

## 폐허 모험

메인 화면에서 "유적 모험"을 선택하세요. 전환 시 원래 실행하던 모드가 종료되고 다시 연결됩니다. 폐허 탐험 페이지에서 휴대폰을 열고 "모험 시작" 또는 스페이스바를 누르세요. 프로그램은 입장, 승격, 보물 팝업창 및 정착을 인식하고, 이를 수락한 후 다음 라운드로 진행됩니다. 일시 중지하고 다시 시작하려면 스페이스바를 사용하세요. 세션을 종료하려면 End 또는 Esc를 누르세요.

보물 상자 보상 페이지가 나타나면 프로그램은 하단의 버튼을 인식하고 자동으로 다음 그룹 또는 나머지 모든 보물 상자를 열고 모험을 계속하기 전에 최종 보상을 확인합니다. 버튼 인식은 텍스트에 의존하지 않습니다.

보스 화면은 기본 승률에 팀원 보너스를 더한 후의 총 승률로 판단됩니다. 기본적으로 일반 보물의 철수율은 45% 미만, 붉은 보물의 철수율은 30% 미만입니다. 두 가지 임계값은 모험 설정에서 조정하거나 기본값으로 복원할 수 있습니다. 각 작업을 클릭하고 화면이 바뀔 때까지 기다립니다. 화면에 변화가 없으면 확인하고 기다린 후 다시 시도하세요. 시뮬레이션된 수동이 활성화되면 착지 지점과 압박 시간이 제한된 범위 내에서 변경됩니다. 보스의 승률은 여러 화면에서 확인해야 합니다. 승률을 확인할 수 없거나 판독값이 충돌하거나 보물 유형을 알 수 없어 의사 결정에 영향을 미칠 경우 약 2.5초 동안 계속 관찰한 후 자동으로 전투합니다. 인터페이스에는 현재 인식된 승률과 결정이 표시됩니다. 게임이 아직 포그라운드에 있고 화면이 유효한지 확인한 후에만 클릭을 보냅니다.

낚시와 탐험은 프롬프트 창의 색상, 모양, 버튼 위치를 기반으로 게임 오류를 식별합니다. 확인 후 녹색 버튼을 누르세요. 화면이 변경되지 않으면 재시도 간격이 연장됩니다. 입장, 갈고리, 경품 인식이 특정 한자와 일치하지 않습니다. 보스 승률은 여전히 ​​화면의 숫자, 퍼센트 기호, 더하기 기호를 식별해야 합니다.

ADB가 입력 결과를 알 수 없다고 보고하면 프로그램은 화면이 바뀔 때까지 기다립니다. 작업 확인 시간이 초과되고 동일한 작업 가능한 화면이 계속 안정적일 때 낚시가 다시 시도됩니다. 탐색은 12초 후에 화면을 다시 인식하게 됩니다. 일시 정지, 연결 해제 또는 화면을 확인할 수 없는 경우 화면을 다시 확인한 후 작동합니다.

## 전경 전환 및 노란색 막대 예측

다른 앱이나 부동 창이 전경을 확보하면 세션은 활성화된 상태로 유지되고 전화기에서 클릭이 일시 중지됩니다. 게임은 전경을 되찾은 것을 확인한 후 자동으로 계속됩니다. 대기 시간 동안 게임 화면과 관련된 타임아웃은 진행되지 않으나, 세션 시간 상한은 실제 시간을 기준으로 계산됩니다. 다른 앱의 위젯에는 클릭이 전송되지 않습니다.

노란색 막대는 터치가 적용되는 순간에 투영된 위상 예측을 사용합니다. 대상은 노란색 막대 안전지대 입구 근처에 있으며 유효 시간의 상한이 설정됩니다. 이전 라운드를 클릭한 후 연속된 두 프레임만 새 노란색 막대가 포인터에 의해 차단되지 않았음을 확인하고 짧은 간격 후에 다음 히트를 계획할 수 있습니다. 변경 사항을 확인할 수 없는 경우 원래의 반복 클릭 방지 기능이 유지됩니다. 예측은 여전히 ​​스트리밍 지연 시간, 터치 지연 시간, 인식 오류의 영향을 받습니다.

설정이 저장되면 제어 스레드에 적용됩니다. 활동을 전환하면 현재 세션이 종료되고 다시 연결됩니다. 확인된 로컬 제어 항목에서 제한된 위치 오프셋을 수정하는 방법을 자동으로 학습합니다. 수동 설정은 사용자가 드래그한 범위 및 포인트 작업을 기반으로 하며 자동 수정은 읽거나 업데이트되지 않습니다. 휴대폰 설정은 로컬 시스템 `phone_settings.json`에만 저장되고 인터페이스 언어는 `tt_tool_ui.json`에 저장됩니다. 자동 보정은 장치 해시, 해상도, 활동 및 선택별로 `device_profiles.json`로 별도로 저장됩니다. 원래 장치 일련 번호, 계정 번호 또는 스크린샷은 저장되지 않습니다. 자동 수정은 설정에서 재설정할 수 있습니다.

## 스크린샷 및 타이밍

처음 연결할 때 PNG 스크린샷을 사용하면 원본 크기와 선택 항목을 얻을 수 있습니다. 일반 실행에서는 대신 `adb exec-out screenrecord` AVC 스트림을 사용하고 FFmpeg는 지속적으로 360픽셀 폭의 프레임으로 디코딩됩니다. 최신 프레임 슬롯은 누적된 인식 작업을 방지합니다. 미리보기는 켜져 있을 때만 그려집니다. 인터페이스는 디코딩 수신, 인식 및 실제 미리보기 그림의 프레임 속도를 각각 표시합니다.

비디오 스트리밍은 연속 출력을 위해 휴대폰에서 지원하는 `--time-limit 0`를 사용합니다. 스트리밍이 예기치 않게 종료되거나 장치의 연결이 일시적으로 끊어지면 계속해서 다시 연결되어 새 이미지를 기다립니다. 이전 버전의 Android가 이 매개변수를 지원하지 않는 경우 추가 조정이 필요합니다. FFmpeg가 존재하지 않거나, 스트림이 중지되거나, 장치 연결이 끊기거나, 화면이 만료되거나, 가로가 회전되거나, 포그라운드 앱이 변경되면 클릭이 더 이상 전송되지 않습니다. 포그라운드 체크는 독립적인 실행 스레드를 사용하며 체크 결과가 만료되면 입력되지 않습니다.

노란색 막대는 원래의 왕복 위상 예측을 따르지만 처음에는 샘플이 항상 오른쪽에 있다고 가정하지 않도록 먼저 샘플의 지속적인 이동과 방향 확인이 필요합니다. 프레임이 오랫동안 정지되어 있거나 방향이 불분명할 경우 노란색 막대 클릭이 전송되지 않습니다. 목표 시간 창이 설정된 불확실성 한계보다 작으면 여행을 건너뜁니다.

`스트림 지연 추정 (ms)`는 60ms로 사전 설정되고, `터치 지연 보정 (ms)`는 80ms로 사전 설정되며, `타이밍 불확실성 여유 (ms)`는 12ms로 사전 설정됩니다. 모두 초기 추정치이며 자동으로 측정된 엔드투엔드 데이터가 아닙니다. USB, 전화, 게임 및 Windows 일정 조정에 따라 달라질 수 있습니다. 모든 물고기나 노란색 막대가 맞을 때마다 보장되지는 않습니다. 인터페이스의 프레임 간격, 화면 수명 및 입력 명령 시간은 호스트 측에서 측정되며 ADB 명령이 반환된다고 해서 실제로 터치가 적용되는 것은 아닙니다.

## 휴대폰 화면 적응

제어 비율은 화면 너비를 기준으로 유지되며 긴 화면의 경우 작업 영역이 하단에 정렬됩니다. 기록 팝업창은 무게 아이콘과 함께 위치하며 확인을 위해 다중 조건 판단에 제출됩니다. 일반 닫기 페이지는 어두운 배경, 황금색 제목 영역, 녹색 직사각형 버튼 및 흰색 픽셀 분포 인식을 결합하고 특정 글꼴을 비교하지 않고 닫기 버튼을 독립적으로 배치합니다. 프레임 선택은 원래 모바일 화면 비율을 사용합니다. 클릭을 보내면 휴대폰의 물리적 픽셀로 돌아갑니다.

`python selfcheck.py`는 입력을 보내지 않고 기존 회귀 및 휴대폰 오프라인 테스트를 실행합니다.
`python build_release.py`는 로컬 데이터를 제외하는 소스 코드 ZIP을 생성합니다.

휴대폰 실제 테스트, 합성 화면 테스트 및 오프라인 재생은 해당 범위만 입증할 수 있으며 테스트 횟수를 사용하여 장기적인 실제 성공률을 추론할 수는 없습니다.

## 1.7.1 업데이트

기본 인식 간격은 0.01초이며 실제 상한선은 여전히 ​​휴대폰 인코딩 스트림의 프레임 빈도에 따라 결정됩니다. 새로운 그림은 이벤트를 통해 제어 루프를 깨우고 최신 프레임 슬롯을 유지합니다. 휴대폰의 일반/노란색 막대 단계의 실제 측정값은 약 55~60FPS입니다. 이는 입력 명령 및 결제 인식 중에 일시적으로 떨어집니다. 동일한 배수로 종단 간 지연을 줄인다고 주장되지는 않습니다.

"Pull Hard" 프롬프트는 더 이상 중국어 간체 문자가 포함된 `bite.png` 템플릿에 의존하지 않습니다. 아래의 보라색 프롬프트 패널, 노란색 가로 막대 및 보라색 원형 버튼이 공동으로 확인된 후 첫 번째 확인 화면에서 진행률 표시줄이 끝날 때까지 기다리지 않고 후크를 당깁니다. 리트랙터 버튼은 독립적으로 위치하며 반복적인 리트랙션을 방지하기 위해 전달 후 단계 변경을 기다립니다.

## 1.7.2 정착 가속화

휴대폰 모드에서 최초 결제 페이지 확인 후 0.25초 정도 기다린 후 수락을 시도합니다. 확인된 결과 페이지에서 여전히 멈춘 경우 0.35초 벤치마크 간격으로 다시 시도하세요(원래 약간의 지터 유지). 아직 입력이 승인되지 않은 경우 첫 번째 클릭 시 게임 애니메이션이 닫힐 것이라는 보장은 없습니다. "타이밍 조정"에서 수정하고 다시 연결하여 적용할 수 있습니다. 시뮬레이터 모드의 원래 기본값은 변경되지 않습니다.

## 1.7.3 수동운전 시뮬레이션

현재 정산 첫 번째 대기 시간은 기본적으로 1초로 설정되어 있습니다. "수동 조작 시뮬레이션"을 선택한 경우:

- 클릭 지점은 게임 선택의 짧은 변의 반경 0.8% 중심 근처의 원 내에서 변경되며 선택에 제한됩니다.
- 짧은 반응 시간은 훅 하강 시 40~120ms, 훅 후퇴 시 15~40ms, 후퇴 시 30~90ms 증가됩니다.
- 노란색이 아닌 막대 작업은 동일한 좌표를 사용하여 누르거나 들어올리고, 35~75ms 동안 누르고 드래그하지 않습니다.
- 정산 재시도는 설정값을 기준으로 ±100ms 정도 변동됩니다.
- 노란색 막대는 착지 지점만 변경하며 적중 창 손상을 방지하기 위해 원래 예측 시간과 일반 클릭을 계속 사용합니다.

고정 착륙 지점을 복원하고 추가 응답 지연을 없애려면 확인란을 선택 취소할 수 있습니다. 설정을 적용하려면 다시 연결해야 합니다. 이는 실제 인물 데이터에 맞춰 보정된 모델이 아닌 입력 변경 사항이며 게임 감지를 방지할 수 없다고 보장되지 않습니다.

## 1.7.4 전경 검사 및 프레임 속도 평가

임시 쿼리가 실패하거나 포커스가 전송되거나 포그라운드 결과가 만료되는 경우 입력이 전송되지 않지만 실행 상태는 즉시 지워지지 않습니다. 동일한 게임인지 다시 확인하고 계속하세요. 동일한 다른 앱을 최소 1초 이상 3회 이상 확인 후 공식적으로 정지됩니다. 불확실한 상태가 3초간 지속되면 "전망 검증이 계속 실패합니다"라고 표시되며 실제 이유가 표시됩니다. 실제 일시 중지 후에도 수동으로 시작해야 합니다.

기본 scrcpy 4.0에서 `--max-fps=120`를 설정하고 프레임 속도=120으로 인코딩하는 실험에서 충돌 전 약 3.95초 동안의 유효 세그먼트는 여전히 약 61FPS였습니다. scrcpy 네이티브 프로그램은 0xC0000005를 제외하고 종료되므로 이 실험은 장기적인 프레임 속도 제한을 증명할 수 없으며 안정적인 대체 백엔드로 사용할 수도 없습니다. 현재 120FPS를 요구하기 위해 채우기/중복 프레임을 사용하지 않고 인증된 원본 스트림을 유지하고 있습니다.

휴대폰 화면은 120Hz를 지원할 수 있지만 이는 현재 게임 화면, 인코딩 경로 및 캡처 파이프라인이 120개의 새로운 화면을 제공한다는 의미는 아닙니다. scrcpy의 max-fps는 상한 설정입니다. 관련 구현에 대해서는 [공식 개발 문서 ](https://github.com/Genymobile/scrcpy/blob/master/doc/develop.md). 이를 두 배로 늘리려면 게임 출력과 안정적인 높은 프레임 속도 캡처 백엔드를 확인해야 합니다.

## 둥근 모서리 인터페이스

새로운 데스크탑 인터페이스는 PySide6을 사용합니다. 창 상단을 드래그하여 이동할 수 있으며, 우측 상단을 최소화하거나 닫을 수 있습니다. 사용자 정의 가능한 둥근 모서리 버튼, 설정 탭 및 상태 영역은 전환 애니메이션을 제공합니다. 연결, 관찰, 시작, 일시 중지 및 ADB 입력은 여전히 ​​원래 모바일 백엔드를 사용합니다. 설정이나 박스 선택을 변경한 후 적용하려면 다시 연결해야 합니다. 창을 닫으면 해당 창에서 시작된 세션이 중지됩니다. 새 버전은 이전 버전의 열려 있는 창을 자동으로 이어받거나 중지하지 않습니다.

## 1.8.1 창 및 전체 미리보기

데스크톱 인터페이스가 시작되면 사용 가능한 화면 공간을 기준으로 기본 크기가 설정되며 상한은 1180×900입니다. 수동 조정 범위는 680×600 ~ 3840×2160 논리 픽셀이며 디스플레이 크기 조정 및 실제 화면 제한이 적용됩니다. 오른쪽 상단 상자는 창을 현재 화면의 사용 가능한 영역(상한을 초과하지 않음)으로 확대하고 다시 누르면 복원됩니다. 오른쪽 하단 모서리를 드래그하여 크기를 조정할 수 있습니다.

너비가 760 미만이고 창이 수직인 경우, 또는 너비가 1200 미만이고 화면비가 0.85 미만인 경우 하향식 배열로 변경되고 시작/일시는 하단에 고정됩니다. 나머지에는 왼쪽 및 오른쪽 열이 사용됩니다. 좁은 수평 창은 X/Y 열이 위아래로 정렬되도록 변경합니다. 높이가 760보다 낮으면 상단 영역이 줄어듭니다. 울트라 와이드 창의 주요 내용은 입력 필드가 과도하게 늘어나는 것을 방지하기 위해 약 1680개의 논리 픽셀 이내로 유지됩니다. 필요에 따라 설정 영역이 스크롤됩니다.

미리보기에서는 인식을 위해 잘린 336×598 화면 대신 전체 휴대폰 스트림을 사용합니다. 외부 프레임은 이미지 종횡비에 따라 크기가 조정되고 둥근 모서리가 적용됩니다. 디스플레이 해상도는 여전히 ADB 스트리밍에 의해 제한되며 둥근 모서리로 인해 모서리 픽셀이 거의 보이지 않습니다. 미리보기를 클릭하거나 미리보기에 초점을 맞춘 다음 Enter/스페이스바를 눌러 더 큰 라이브 화면을 엽니다. 미리보기 FPS는 그려지는 새 프레임의 실제 수를 기반으로 계산됩니다. 뷰포트가 가려지거나 숨겨져 있으면 드롭될 수 있습니다. 원래 Tk 인터페이스는 여전히 인식 주석 미리보기를 유지합니다.
