# 균열 청소: 크로노모델 및 증거

[English](SWEEP-TIMING.md) · [繁體中文](SWEEP-TIMING.zh-TW.md) · [日本語](SWEEP-TIMING.ja.md) · 한국어

> 이 기술 문서에는 이전 버전과 측정 기록이 포함되어 있습니다. 현재 설치 방법과 지원 기능은 [기본 안내서](../README.ko.md)를 참고하세요.

## 견본

- Android 1.1.6, 버전 코드 120733181, arm64-v8a. 에뮬레이터에 의해 설치된 세 개의 APK는 로컬 저장 파일의 SHA-256과 일치합니다. arm64 분할은 `7fdd866a18ae22c139e84be7ab2c5a2dded7a5e000961f3cd3e49c12cb662103`입니다.
- `libil2cpp.so` SHA-256: `1223d55a9903364c283fac07f96102410c8adec128add3888e9cb4fb80c67e9c`. 다음 주소는 ELF 가상 주소이며 실제 파일 오프셋은 PT_LOAD에 따라 변환되어야 합니다. Cpp2IL 출력의 원래 분해를 올바른 주소의 기계어 코드로 간주하지 마십시오.

## 게임 로직

- `PopupRiftSweepMinigame.PlayTiming`(0x57e6ed8)는 위치 0부터 시작하여 매번 `Random.Range(minRoundTripTime, maxRoundTripTime)`로 왕복 시간 `T`를 펌핑하고 속도는 `2/T`로 설정됩니다.
- `TimingGauge.Update` (0x57c4680) 매 프레임마다 `position += velocity * Time.unscaledDeltaTime`로 업데이트됩니다. 끝점까지 클립하고 막대 모드가 0 또는 1에 도달하면 반전합니다. 끝점 너머 부분은 이상적인 반사에 의해 보존되지 않습니다.
- `TimingBarGauge.ToX`(0x57c4308)은 내부 위치를 `(position - 0.5) * trackWidth`로 변환합니다. 사진은 손상되지 않고 장애물 없이 유지되어야 합니다. 크기 조정된 픽셀 좌표는 내부 게임 좌표가 아닙니다.
- `TimingGauge.Judge`(0x57c47bc)는 각 판단 영역 너비의 절반을 `abs(position - center)`와 비교합니다. 바 모드는 이 거리를 직접 사용합니다. `ShowResultAsync` 먼저 포인터를 정지한 후 판단하십시오.
- 읽기 전용 실행 기간 데이터는 이 샘플의 `perfectRatio=0.04`, `coolRatio=0.2`, `niceRatio=0.4`, `minRoundTripTime=0.7` 및 `maxRoundTripTime=1.8`를 보여줍니다. 이는 샘플 빌드 및 화면 설정을 관찰한 결과이며, 다른 빌드나 콘텐츠는 다를 수 있습니다.

## 어시스턴트 모델 및 제한사항

보조자는 화면에서 포인터와 노란색 영역의 중심을 추적합니다. 캡처 시간 지터를 줄이기 위해 속도를 추정하기 위해 일정 기간 동안 동일한 방향으로 쌍을 이루는 속도의 중앙값을 사용합니다. 이는 단지 현재 여행을 예측할 뿐 손실 없이 끝점을 통과할 수 있다고 가정하지 않습니다. 반대 방향을 관찰한 후 속도를 다시 추정합니다. 보정은 화면 및 입력 지연을 추정하고 실제 정지할 때마다 장치의 지연 설정을 수정합니다. 이 모델은 게임 메모리를 읽거나 수정하지 않으며 루트에 의존하지 않습니다.

Raiden의 논스톱 입력 관찰에서 창은 약 122FPS를 캡처했습니다. 화면을 동시 읽기 전용 게임 위치와 비교하면 디스플레이가 약 23ms 지연되는 것으로 추정됩니다. ADB 스트림에 대한 또 다른 관찰에서는 약 100ms로 추정됩니다. 이러한 수치에는 샘플링 및 동기화 오류가 포함되며 다른 컴퓨터의 고정 지연으로 간주되어서는 안 됩니다. 창 관찰의 오프라인 재생에서 완전한 비교 데이터가 부족한 초기 교차를 제외하고 후속 4개의 예측은 모두 내부 완전 구간에 속했습니다. 이는 실제 키 적중률이 아닙니다.

위에서 모든 적중이 보장된다고 추론할 수는 없습니다. 화면 업데이트, 시스템 예약 및 입력 지연이 모두 변동됩니다. 실제 게임 테스트 결과와 실행 파일 검증은 별도로 보고해야 합니다.

## 창문 및 공간의 실제 측정

시작/중지 위치에서 공간을 바인딩한 후 Thunderbolt Simulator는 Windows 창을 사용하여 공간 작업을 캡처하고 시뮬레이션합니다. ADB 또는 루트를 사용하지 않습니다. 한 번 계산을 잘못한 후 두 번째 중지 전에 게임이 닫혔다가 다시 열렸으며 투표 수는 여전히 10개입니다. 이후 수동 테스트 스크립트와 전체 Qt 인터페이스 테스트가 각각 완료되었으며 정지된 화면을 기반으로 한 두 계산 모두 노란색 영역에 빠졌습니다. Qt 인터페이스 라운드의 두 중심 오류는 화면 너비의 약 0.81%와 0.13%였습니다. 또 다른 완전한 인터페이스 테스트에서는 두 개의 스크린샷이 유지되지 않아 판단이 유추되지 않았습니다. 이는 동일한 컴퓨터의 작은 샘플일 뿐이며 적중률이나 다른 컴퓨터를 보장하지 않습니다.

## 캡처 간격 및 정렬 불량 분석

이전 인터페이스 실행을 위한 중간 획득 간격은 약 6.3ms이고, 95번째 백분위수는 28.4ms이며, 최대값은 131ms입니다. 전체 이미지를 미리 보는 것과 심사하는 것은 동일한 스레드를 공유합니다. 창 미리보기를 별도의 스레드로 이동하고 보정 파일 작성을 연기한 후 게임 입력이 없는 관찰 결과 중앙값은 8.9ms, 95번째 백분위수는 17.8ms, 최대값은 97.1ms였습니다. 두 로드는 동일하지 않으며 제어된 성능 비교로 간주될 수 없습니다.

수정 후 창과 공간의 실제 측정에서는 첫 번째 화면은 노란색으로 해석되었고, 두 번째 화면과 사용자 관찰은 모두 시기상조와 보라색으로 해석되었습니다. 연속 화면 추정에 따르면 버튼을 누르기 전의 위치에서 정지 위치까지의 시간은 각각 약 80ms와 65ms입니다. 두 번째 노란색 절반 너비는 약 7ms만 허용합니다. 이 추정치는 화면 지연, 캡쳐 오류 등을 포함해 게임 내 이벤트의 정확한 시간이라고 볼 수는 없으나, 현재 프로세스로는 아직 적중을 보장할 수 없음을 보여준다. 새로운 보호 기능은 창 캡처 간격이 35ms를 초과하고 시스템이 전송되지 않은 키 입력을 취소하고 다음 패스를 기다리기 위해 예정된 시간 이후 6ms 이내에 깨어나지 못하는 경우 속도를 다시 평가합니다. 모든 입력을 감지하거나 대기 시간 변화를 나타낼 수는 없습니다.
