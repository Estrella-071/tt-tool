# Windows インストール不要のポータブル版

[English](WINDOWS.md) · [繁體中文](WINDOWS.zh-TW.md) · 日本語 · [한국어](WINDOWS.ko.md)

> この技術資料には過去のバージョンと測定記録が含まれます。現在のセットアップと対応機能については[メインガイド](../README.ja.md)を参照してください。

## 一般ユーザー

プロジェクトの GitHub リリースで `tt-tool-emulator-版本号-Windows-x64.zip` を選択し、完全に解凍して、`启动钓鱼助手.bat` をダブルクリックします。対応するバージョンがダウンロード ページで既に入手可能かどうかは、プロジェクトの実際のリリースによって決まります。ポータブル パッケージの代わりに、GitHub で自動的に生成されたソース コード ZIP をダウンロードしないでください。

64 ビット Windows 10/11 に適用されます。このパッケージには、独立した CPython、Tcl/Tk、NumPy、OpenCV、Pillow、および MSS が付属しています。 Python、Anaconda、PyCharm をインストールしたり、追加の pip を実行したりする必要はありません。また、初めて起動するときにコンポーネントをダウンロードする必要もありません。 LDPlayer または MuMu のシミュレータとゲームは依然として自分で準備する必要があります。このプログラムは、システムの Python、レジストリ、または PATH を変更しません。

ルート ディレクトリの `app/` は完全なプロジェクト ソース コードとリソースを保存し、`runtime/` は独立した実行環境を保存し、`data/` は実行後のローカル構成、ログ、スクリーンショット、およびビデオを保存します。エントリをダブルクリックしてパッケージ インタープリターの分離モードを使用し、ユーザーがインストールした Python パッケージと PYTHONPATH を読み取らないようにします。

現在のアカウントが書き込み可能な場所に解凍します。圧縮パッケージのプレビュー ウィンドウ、読み取り専用ディスク、または書き込みに高い権限が必要なシステム ディレクトリには配置しないでください。同じデータ ディレクトリを繰り返し起動すると、すでに開いているウィンドウに切り替えるように求められます。異なるフォルダーに別々のコピーを作成しても、同じエミュレータを同時に制御することは避けるべきです。

初めて使用する場合でも、スペース マッピングを設定し、ウィンドウを選択し、ゲーム領域全体をフレーム化し、スタート ボタンまたはショートカット キーを使用して釣りを開始する必要があります。操作手順については [README](../README.ja.md) を参照してください。

## アップデートとトラブルシューティング

- 更新: まず古いバージョンを終了し、新しいパッケージを新しいフォルダーに抽出します。古いディレクトリのバックアップを保存してください。設定を継承する必要がある場合は、古い `data/` の `config.json` と `speed_profile.json` を新しいパッケージの `data/` にコピーするだけです。存在しないファイルを作成する必要はありません。ソース バージョンから移行する場合は、これら 2 つのファイルをプロジェクトのルート ディレクトリにコピーします。過去のスクリーンショットとビデオは引き続き古いディレクトリに保持できます。
- 開けません: `检查运行环境.bat` をダブルクリックして、表示されたエラーを保持します。起動エラーは `data/logs/startup.log` に書き込まれます。未チェックのエラー ログを公開しないでください。
- ファイルが傍受または欠落しています。ファイルがプロジェクト リリース ページからのものであるかどうか、検証値が一貫しているかどうかを確認し、システム プロンプトに従います。日常的な手順としてセキュリティ ソフトウェアをオフにしないでください。
- 一貫性のない権限: エミュレータが管理者として実行されている場合、アシスタントは同じ権限で実行されているとみなされます。
- 共有: 作成したオリジナルの ZIP を公開します。既に使用したポータブル ディレクトリを再圧縮しないでください。

## メンテナーが再生する

ウェアハウスのルート ディレクトリから実行します。

```bash
python build_windows.py
```

ビルド エントリには、Python 3.10 以降の標準ライブラリのみが必要です。最初のビルドではインターネット接続が必要で、オペレーティング環境と Windows の依存関係を固定リストからダウンロードし、SHA-256 を 1 つずつチェックします。 `.build-cache/` のファイルは後で再利用できます。このビルドでは、ネイティブ `config.json` を読み込んだり、ログ、スクリーンショット、ビデオを最終製品に取り込んだりすることはありません。

出力は`dist/tt-tool-emulator-版本号-Windows-x64.zip`です。 Windows ホスト上でのビルドでは、パッケージ インタープリタを使用して Tk、ImageTk、画像テンプレート、ビデオ コーデック、および表示インターフェイスをチェックします。このチェックでは、スクリーンショットを撮ったり、キーストロークを送信したりしません。同じポータブル パッケージを他のオペレーティング システムでもアセンブルできますが、バイナリ構造とファイルの整合性チェックは Windows ランタイム検証と同等ではありません。公開する前に、Windows 上でインターフェイス、フレーム選択、一時停止、および実際のシミュレーターの動作を確認する必要があります。

ソース コードを GitHub にアップロードした後、「**Actions → Windows portable → Run workflow**」と入力することもできます。ワークフローは Windows マシン上で構築およびチェックされ、成功するとダウンロード可能なビルド製品が提供されます。ダウンロード後にポータブル ZIP を GitHub リリースに手動で追加します。ワークフローではリリースが自動的にリリースされません。ウェアハウスには `.github/workflows/windows-portable.yml` が含まれている必要があり、ドットで始まるディレクトリを見逃さないでください。

`packaging/windows-runtime.lock.json` 依存関係のバージョン、ソース、ハッシュを修正しました。依存関係を更新するときは、Windows x64/Python 3.12 の互換性とライセンスも確認し、リストを更新する前に実際のダウンロードを確認する必要があります。バージョン文字列を変更するだけではありません。現在ロックされているパッケージには、wheel 用の追加の `.data` インストール ディレクトリがありません。このような依存関係を追加するには、まずビルド ルールを展開してテストする必要があります。

このプロジェクトは、独立した実行環境ディレクトリを使用してインストール不要を実現し、ユーザーのコンピュータ上で単一の EXE ファイルを一時的に解凍する必要はありません。ポータル、アプリ、ランタイムは常に一緒に配布してください。ソース コードは明示的なファイル マニフェストから生成されます。サードパーティのバイナリはアップストリーム ライセンスを保持し、バージョンとダウンロード ソースはパッケージ `DEPENDENCIES.json` に記録されます。
