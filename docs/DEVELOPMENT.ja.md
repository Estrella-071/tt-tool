# 開発と検証

[English](DEVELOPMENT.md) · [繁體中文](DEVELOPMENT.zh-TW.md) · 日本語 · [한국어](DEVELOPMENT.ko.md)

このページは従来のエミュレーターとデスクトップの開発手順を説明します。現在の Android 端末向けアプリと Windows インストーラーについては、[ADB 端末向け開発](ADB.ja.md)と [Windows インストーラー](INSTALLER.ja.md)を参照してください。

＃＃ 構造

- `main.py`: Tkinter インターフェイス、ウィンドウの選択、設定、プレビュー スイッチ。
- `fisher/vision.py`: 画像の正規化、色およびローカル テンプレートの認識。
- `fisher/controller.py`: フィッシングフェーズ、カウント制限、結果の再試行、およびアクションの送信。
- `fisher/phase.py`: 比例座標、三角波運動位相、双方向到着時間、同一トリップ重複排除。
- `fisher/runtime.py`: 固定周波数スクリーンショット、キャンセル可能な独立したキー持続時間、制御コマンドおよび入力調整。
- `fisher/scheduling.py`: スクリーンショットのリズムとショートカット キーのエッジ。
- `fisher/speed.py`: 基準速度、明示的な堅牢なキャリブレーション、およびネイティブ パラメーターの保存。
- `fisher/contact.py`: 共有制限付き遅延補償と履歴戦略比較の実装。
- `fisher/emulators.py`: LDPlayer/MuMu タイトル フィルタリング、手動選択フォールバック、および選択の所有権の検証。
- `fisher/windows.py`: ウィンドウ座標、前景チェック、スペース注入/解放。
- `fisher/config.py`: 構成の検証、移行、およびアトミック保存。
- `fisher/packaging.py`: 公開ファイルのリストと ZIP 整合性チェック。
- `desktop.py`、`build_windows.py`: オプションのポータブル スタートアップおよびビルド ツール。

ソース コードは `main.py` から開始して実行され、公式インターフェイスでは一律に `phase` 戦略が選択されます。過去の `contact` および `center` の実装には、互換性と回帰制御のみが保持されています。彼らのテストは元の構成を明示的に修正し、過去の高周波サンプルを低周波戦略の検証とはみなしません。

`ROOT` は静的リソース用で、`DATA_ROOT` はネイティブ設定用です。パブリック ファイルを追加するときに `PUBLIC_FILES` を同期します。ローカル構成、診断データ、またはスクリーンショット ディレクトリ全体をリストに追加しないでください。

## 決定と入力

コントローラーは、システム入力の呼び出しに成功した後にのみ、アクションと `commit()` を提案します。フェーズ戦略の将来の HIT は、唯一の保留中の実行スロットに入ります。新しい写真があれば古い計画が置き換えられ、未知の写真や判断がつかない段階では計画がキャンセルされます。このループは、数秒間待機するブロック呼び出しを使用せずに、スクリーンショット間隔中のキーストロークの有効期限も処理します。期限が近づくと、スクリーンショットの撮影は延期され、入力が先に処理されます。

フェーズ プランでは、ヒストリカル ストラテジの 80/120 ミリ秒のフレーム期間制限を適用できません。その予測範囲は、現在のフェーズと次の観測によって制限されます。 F9、フォーカス外、ウィンドウ変更、終了でも入力はキャンセルされます。動作フェーズは入力後も保持されます。ターゲットから離れると同じトリップロックが解除され、ターゲットが変わると次のラウンドを開始できます。

結果ページのレコード スタイルとクレーム スタイルは、待機/再試行プロセスを共有します。最初の確認後待機し、その後の予定については 1 秒ごとに再試行します。確認しない場合、または結果ページから離れた場合は、閉じるアクションを停止します。緑色のボタンがあるからといって、最初の釣りインターフェイスを満足していると受け入れないでください。 [承諾] ボタンは白いテキスト マスクに一致し、0.90 ～ 1.15 倍の制限されたサイズのテンプレートをキャッシュします。緑の領域、暗い背景、タイトルが確認され、元のローカル検索位置と最小しきい値 0.72 が維持された後にのみ実行されます。

`TRIAL_BUILD=False` は公式ビルドであり、トレース レコーダーやセッション ログは作成されず、一時停止時に ZIP はエクスポートされません。履歴診断モジュールは、明示的な開発ツールおよび回帰依存関係としてのみ保持されます。手動再生とテスト出力は、通常の釣り操作パスの一部ではありません。

タイミング アルゴリズムと境界については、「アルゴリズムの説明 ](ALGORITHM.ja.md)」を参照してください。現在のモデルは均一な速度を想定しており、ゲームの長い一時停止を解決された問題として扱いません。低頻度のスクリーンショットでは、方向と速度が一意に推測できると主張すべきではありません。

＃＃ 確認する

```bash
python selfcheck.py
python replay.py
python build_release.py
```

セルフテストではシステム キーストロークは送信されません。 `test_phase.py` には、完全なランタイム ループのシミュレーションが含まれています。つまり、それぞれ 100 ミリ秒と 500 ミリ秒でサンプリングし、2 つのスクリーンショット間で HIT を実行します。左右のリエントリー、狭いストリップ、マルチラウンドターゲット、正規化されたズーム、一時停止/焦点外れ/不明/サイズ変更のキャンセル、および暗号化されていないスクリーンショットのキャリブレーションと自動実行データ生成の検証。古い戦略、決済、スクリーンショットの予算、ショートカット キー、入力リリース、プライバシー、およびパッケージ化の境界は引き続き戻ってきます。

テスト資料では、必要なローカル ゲーム コントロールと感度を下げたフレーム選択の例を使用します。合成軌跡やビデオ再生は実際のゲームの成功率を証明することはできず、オフライン検査は Windows ネイティブ ウィンドウ、DPI、マルチスクリーン、および実際のシミュレーターの検証とは依然として区別される必要があります。

構成バージョン 7 を初めてアップグレードすると、連続フィッシングが有効になり、古いデフォルトのサンプリング間隔 30 が 6 に変更され、その他のカスタム サンプリング値、ショートカット キー、待機およびその他の設定が保持されます。新しいバージョンで保存された選択内容はデフォルト値で上書きされなくなりました。古い選択内容は、所有権、タイトル、サイズが一致している場合にのみ再利用されます。明示的なキャリブレーション スイッチは、このモニタリングに対してのみ有効です。速度ファイルではスケールと統計フィールドのみが許可され、生の軌跡やウィンドウ情報は保存されません。

送信前にセルフチェックとパブリック パッケージ化を実行し、ソース コード マニフェスト、サンプル構成、およびイメージにネイティブ プライバシーが含まれていないことを確認します。 LICENSE に従って配布し、サードパーティの重要な通知を保持します。オプションのポータブル ビルドについては、[WINDOWS.md](WINDOWS.ja.md)] を参照してください。
