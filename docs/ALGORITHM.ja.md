# 黄色のバーのクリックタイミング

[English](ALGORITHM.md) · [繁體中文](ALGORITHM.zh-TW.md) · 日本語 · [한국어](ALGORITHM.ko.md)

> この技術資料には過去のバージョンと測定記録が含まれます。現在のセットアップと対応機能については[メインガイド](../README.ja.md)を参照してください。

スクリーンショットとキーストロークでは 2 つの独立した期間が使用されます。スクリーンショット間のデフォルトの間隔は 100 ミリ秒です。保留中のキーストロークは、次のスクリーンショットを待たずに、制御ループによって個別にチェックされます。通常、制御ループは 10 ミリ秒ごとに処理を譲り、キーを押す期限が近づくと残りの時間待機します。実際のウェイクアップ精度は Windows のスケジュールに依存します。

## 往復運動

トラックの表示フレーム幅は 1 で、デフォルトの速度は 0.606 ライン/秒です。魚の浮きの中心の左右の端点は、トラックの装飾が中心のストロークとして取られるのを避けるために、同じ座標系で 0.083 と 0.940 を採用します。 1往復は約1.41秒です。正規化された画像は制御の位置決めにのみ使用され、速度は元の画面解像度には依存しません。

運動位相は常に前方に増加し、位置は三角波によって軌道にマッピングされます。終点に到達しても方向が逆転するだけで、速度はリセットされません。最初の識別はデフォルトで右に設定され、その後は時間に基づいて自動的にエンドポイントを通過します。新しいスクリーンショットは、予測に最も近い往復分岐への位置を投影し、2 つの画像の変位符号のみに基づいて方向を推測することを回避します。複数の黄色のバーのラウンドでは、同じフェーズの動きを使用し続けます。

## クリックルール

- 入力が有効になるまでの観測位置を予測します。その時点でまだ黄色の範囲内にある場合はすぐにクリックし、そうでない場合は次のパスを予約します。
- 未入力：次に黄色のバーの真ん中を通過する時間を計算し、入力遅延を差し引いた後にクリックをスケジュールします。左右の方向と、最初に折り返さなければならないパスの両方が計算に含まれます。
- 黄色のバーが非常に狭い場合でも、固定ピクセルマージンがバーの幅より大きいため、中央部分が計算され、クリックは禁止されません。
- 実行される計画は次の画像までに更新されます。未知の写真、他のステージ、一時停止、焦点が合っていない、またはウィンドウ サイズの変更により、計画がキャンセルされます。
- 同じ旅行で最大 1 回クリックできます。黄色のバーが変化すると、次のラウンドに進むことができます。黄色のバーが変化しない場合は、永続的なロックや限定的な再試行に頼ることなく、出発後に次にそのバーを通過するときに再試行できます。
- 魚のフロートが黄色をブロックすると、確認された完全な境界が保持され、残りの色の小さなセグメントが新しいターゲットとして扱われることが回避されます。

キーが近づくと、最初に入力が処理され、次にスクリーンショットが撮影されます。すべてのプランでは、現在のウィンドウと緊急一時停止のチェックが保持され、キャンセルできない長い休止状態は使用されません。ヒット ウィンドウ全体が経過した後、次のパスが再計算されます。

## 速度と遅延

固定速度はローカルキャリブレーションファイルから読み取られ、保存されていない場合は基準値が使用されます。キャリブレーションを明示的にチェックした後は、通常のサンプリングにおける同じ方向の間隔のみが使用されます。インターバルの開始点を高頻度で保持し、0.25 秒以上蓄積した後に速度を再推定し、キーを押すか戻るとインターバルを再取得します。クロスエンドポイント、入力モーションの近くの影響、ゼロ変位、明らかな異常な速度は除外され、外れ値は中央値と MAD によって除外されます。双方向サンプルが安定すると、比率、サンプル数、分散が保存され、キャリブレーションが停止します。元の軌跡は保存されず、追加のスクリーンショットは暗号化されません。

ゲームの応答遅延ベンチマークのデフォルトは 40 ミリ秒で、手動で調整できます。ローカル補正は予定時刻からシステム入力実行までの計測可能な部分のみを計測し、単独補正とトータル補正には上限がございます。これはゲームの内部受信時間と同じではなく、画面の変化に基づいてゲーム全体の遅延を測定するとも主張しません。

## 適用境界

この戦略は、最初の方向が右方向で、2 つのスクリーンショット間の動きがほぼ均一であることを前提としています。低頻度のスクリーンショットでは、短いフック プロンプトが見逃される可能性があり、方向、速度、一時停止を同時に決定できません。黄色のバーを途中で再開した場合、最初の方向が実際とは逆になる場合があります。フックをセットする準備をするときに始めることをお勧めします。ゲームの一時停止、大幅な速度の変更、長時間にわたるシステムの混雑、視覚的なミスなどにより、押し忘れや誤操作が発生する可能性があります。

フリーズ フレーム検出は現在、スケジュールされた入力をブロックするために使用されていません。画像認識には依然として完全なフレーム選択が必要であり、ゲーム レイアウトはテンプレートに対応できます。アスペクト比を変更するには、コントロールを再配置するときに再適応する必要があり、比例速度は視覚的な適応に代わることはできません。

スクリーンショット、トレース、ログ、または診断パッケージは、実行時に自動的に保存されません。手動のスクリーンショット/記録および明示的なキャリブレーションのみが、対応するネイティブ ファイルに書き込まれます。
