# ADBモバイルモード

[English](ADB.md) · [繁體中文](ADB.zh-TW.md) · 日本語 · [한국어](ADB.ko.md)

Windows パソコンから USB で Android 端末を接続します。端末への APK のインストールや root は不要です。

## はじめに

1. Windows x64 版をインストールし、[インストールガイド](INSTALLER.ja.md)に従って Android SDK Platform-Tools と FFmpeg を準備します。
2. 端末で USB デバッグを有効にしてパソコンを許可し、ゲームを縦向きで開きます。
3. tt tool を開きます。許可済みの端末が 1 台の場合は自動接続します。複数ある場合は端末を選んで接続します。
4. アクティビティを選択した後、「設定」を開き、「自動学習」または「手動設定」を選択し、携帯電話でドラッグ範囲のコーナーと操作点をプレビューします。タイミングと避難閾値はスライダーで調整でき、デフォルトに戻すこともできます。 2 つのモードの設定は個別に保存され、保存後すぐに適用されます。
5. 「釣りを開始」またはスペースバーを押して開始し、もう一度押すと一時停止します。カウントとセッション時間は一時停止中も保持されます。 「End」または Esc を押してセッションを終了し、次回からカウントを再開します。

フックをセットしたり、フックを引いたりしても画面が変化しない場合、携帯電話フィッシングは画面がまだ安定していることを確認した後、自動的に再試行します。同じフックを再試行しても、カウントは繰り返し表示されません。一時的に画面が確認できない場合は観察を継続し、認識が回復してから続行します。フック数の上限を設定する場合、リトライも操作数の上限に含まれます。制限時間はまだ有効です。

## 遺跡の冒険

メイン画面で「遺跡アドベンチャー」を選択します。切り替えると、最初に実行されたモードが終了して再接続されます。遺跡探索ページで携帯電話を開き、「冒険を始める」またはスペースバーを押してください。プログラムは入場、進行、宝のポップアップウィンドウ、決済を認識し、それを受け入れると次のラウンドに進みます。スペースバーを使用して一時停止したり再開したりできます。 End または Esc を押してセッションを終了します。

宝箱の報酬ページに遭遇すると、プログラムは下部のボタンを認識し、次のグループまたは残りのすべての宝箱を自動的に開き、冒険を続行する前に最終的な報酬を確認します。ボタンの認識はテキストに依存しません。

ボス画面は基本勝率に味方ボーナスを加えた合計勝率で判定されます。デフォルトでは一般宝物の避難率は45%未満、赤宝物の避難率は30%未満です。 2 つのしきい値は、アドベンチャー設定で調整したり、デフォルトに戻すことができます。各操作をクリックして、画面が変わるまで待ちます。画面が変わらない場合は、確認して待ってからもう一度お試しください。擬似マニュアルを有効にすると、着地位置と押下時間が一定の範囲で変化します。ボスの勝率は複数画面で確認する必要がある。勝率が確認できない場合や、数値が矛盾している場合、宝の種類が不明で意思決定に影響を与える場合は、約2.5秒間観察を続けた後、自動で戦闘します。インターフェイスには、現在認識されている勝率と決定が表示されます。ゲームがまだフォアグラウンドにあり、画面が有効であることを確認した後にのみクリックが送信されます。

釣りや探検では、プロンプト ウィンドウの色、形、ボタンの位置に基づいてゲーム エラーを特定します。確認後、緑色のボタンを押します。画面に変化がない場合、リトライ間隔が延長されます。入口、フック、賞品の認識が特定の漢字と一致しません。ボスの勝率を確認するには、画面上の数字、パーセント記号、プラス記号を識別する必要があります。

ADB が入力結果が不明であると報告した場合、プログラムは画面が変わるまで待機します。操作確認がタイムアウトし、同じ操作可能な画面が安定し続けた場合、釣りはリトライされます。探索は 12 秒後に画面を再認識します。一時停止や切断、画面が確認できない場合は、操作前に画面を再確認します。

## フォアグラウンド切り替えとイエローバー予測

他のアプリまたはフローティング ウィンドウがフォアグラウンドを取得すると、セッションは有効なままになり、電話機でのクリックは一時停止されます。ゲームはフォアグラウンドに戻ったことを確認した後、自動的に続行されます。待機期間中はゲーム画面に関するタイムアウトは進みませんが、セッション時間の上限は実際の時間に基づいて計算されます。これにより、他のアプリのウィジェットにクリックが送信されなくなります。

黄色のバーは、タッチが有効になる瞬間に投影される位相予測を使用します。ターゲットは黄色のバーの安全地帯の入り口付近にあり、効果時間の上限が設定されます。前のラウンドでクリックした後、連続 2 フレームだけで、新しい黄色のバーがポインターによってブロックされていないことが確認され、短い間隔の後に次のヒットを計画できます。変更が確認できない場合は、元の反復クリック保護が維持されます。予測は依然としてストリーミング遅延、タッチ遅延、認識エラーの影響を受けます。

設定が保存されると、制御スレッドに適用されます。アクティビティを切り替えると現在のセッションが終了し、再接続されます。確認されたローカル制御項目から制限された位置オフセットを修正する方法を自動的に学習します。手動設定は、ユーザーがドラッグした範囲およびポイント操作に基づいており、自動補正は読み取られたり更新されません。携帯電話の設定はローカル マシン `phone_settings.json` にのみ保存され、インターフェイス言語は `tt_tool_ui.json` に保存されます。自動キャリブレーションは、デバイス ハッシュ、解像度、アクティビティ、選択ごとに `device_profiles.json` として個別に保存されます。元のデバイスのシリアル番号、アカウント番号、またはスクリーンショットは保存されません。自動補正は設定でリセットできます。

## スクリーンショットとタイミング

初めて接続するときに、PNG スクリーンショットを使用して、元のサイズと選択範囲を取得します。通常の実行では、代わりに `adb exec-out screenrecord` AVC ストリームが使用され、FFmpeg は 360 ピクセル幅のフレームに継続的にデコードされます。最新のフレーム スロットにより、蓄積された認識作業が回避されます。プレビューは、オンになっている場合にのみ描画されます。インターフェイスには、デコード受信、認識、実際のプレビュー描画のフレーム レートがそれぞれ表示されます。

ビデオ ストリーミングでは、携帯電話でサポートされている `--time-limit 0` を使用して連続出力を行います。ストリーミングが予期せず終了したり、デバイスが一時的に切断された場合でも、デバイスは再接続を続けて新しい画像を待ちます。 Android の古いバージョンがこのパラメータをサポートしていない場合は、追加の調整が必要です。 FFmpeg が存在しない場合、ストリームが停止した場合、デバイスが切断された場合、画面の有効期限が切れた場合、風景が回転した場合、またはフォアグラウンド アプリが変更された場合、クリックは送信されなくなります。フォアグラウンド チェックでは独立した実行スレッドが使用され、チェック結果は有効期限が切れても入力されません。

黄色のバーは元の往復位相予測に従いますが、最初にサンプルが常に右方向であると仮定することを避けるために、最初にサンプルの継続的な移動と方向の確認が必要です。フレームが長時間フリーズしている場合や方向が不明瞭な場合は、黄色のバーのクリックは送信されません。目標時間ウィンドウが設定された不確実性マージンより小さい場合、トリップはスキップされます。

`配信遅延の推定（ミリ秒）` は 60ms、`タップ遅延の補正（ミリ秒）` は 80ms、`タイミングの不確実性（ミリ秒）` は 12ms にプリセットされます。すべては初期推定値であり、自動的に測定されたエンドツーエンドのデータではありません。 USB、電話、ゲーム、Windows のスケジュール調整の対象となります。すべての魚や黄色のバーのヒットが保証されるわけではありません。インターフェイスでのフレーム間隔、画面経過時間、およびコマンド入力時間はホスト側で測定され、ADB コマンドが返されたからといって、タッチが実際に有効になるわけではありません。

## 携帯電話の画面適応

コントロールの比率は画面の幅に基づいて維持され、操作領域は長い画面の下部に配置されます。レコードポップアップウィンドウには重量アイコンが配置され、確認のために複数条件の判定が行われます。通常の閉じるページは、暗い背景、金色のタイトル領域、緑色の長方形ボタン、および白色のピクセル分布認識を組み合わせ、特定のフォントを比較することなく独立して閉じるボタンを配置します。フレーム選択では、元のモバイル画面比率が使用されます。クリックを送信すると、携帯電話の物理ピクセルに戻ります。

## 確認する

`python selfcheck.py` は、入力を送信せずに既存の回帰テストと携帯電話オフライン テストを実行します。
`python build_release.py` ローカル データを除外したソース コード ZIP を作成します。

携帯電話の実際のテスト、合成画面のテスト、およびオフライン再生は、対応する範囲を証明することしかできず、テストの数を使用して長期的な実際の成功率を推測することはできません。

## 1.7.1 アップデート

デフォルトの認識間隔は 0.01 秒ですが、実際の上限は携帯電話のエンコード ストリームのフレーム周波数によって決まります。新しいピクチャはイベントを通じて制御ループを起動し、最新のフレーム スロットを保持します。携帯電話の通常/イエローバーフェーズの実測値は約55～60FPSですが、コマンド入力時や決済認識時に一時的に低下します。エンドツーエンドの遅延を同じ倍数だけ削減するとは主張されていません。

「Pull Hard」プロンプトは、簡体字中国語の `bite.png` テンプレートに依存しなくなりました。紫色のプロンプト パネル、黄色の水平バー、および下の紫色の丸いボタンが同時に確認された後、プログレス バーの終わりを待たずに、最初の確認画面でフックがプルされます。リトラクターボタンは独立して配置されており、繰り返しのリトラクトを避けるために、配送後の段階の変更を待ちます。

## 1.7.2 沈下加速

携帯電話モードで初めて決済ページを確認した後、0.25秒待ってから受け付けてください。まだ確認結果ページでスタックしている場合は、0.35 秒のベンチマーク間隔で再試行してください (元のわずかなジッターを維持)。入力をまだ受け付けていない場合、最初のクリックでゲーム アニメーションが閉じるという保証はありません。 「タイミング調整」で変更し、再接続して適用できます。シミュレータ モードの元のデフォルトは変更されません。

## 1.7.3 手動操作シミュレーション

現在の決済の最初の待ち時間のデフォルトは 1 秒です。 「手動操作をシミュレートする」にチェックを入れた場合：

- クリック ポイントは、ゲーム選択範囲の短辺の半径 0.8% の中心付近の円内で変化し、選択範囲に限定されます。
- 短い反応時間はフック下げで40～120ms、フックの引き込みで15～40ms、引き込みで30～90ms増加しました。
- 黄色以外のバー操作では、同じ座標を使用して押す/持ち上げ、35 ～ 75 ミリ秒間押し続け、ドラッグしません。
- 決済リトライは設定値を中心に±100ms変動します。
- 黄色のバーは着地点を変更するだけで、ヒット ウィンドウの損傷を避けるために元の予測時間と通常のクリックが引き続き使用されます。

ボックスのチェックを外すと、固定着地点が復元され、追加の応答遅延がなくなります。設定を適用するには再接続する必要があります。これらは入力の変更であり、実際の人物のデータに合わせて調整されたモデルではなく、ゲームの検出を回避できる保証はありません。

## 1.7.4 フォアグラウンド検査とフレームレート評価

一時的なクエリが失敗した場合、フォーカスが転送された場合、またはフォアグラウンド結果の有効期限が切れた場合、入力は送信されませんが、実行ステータスはすぐにはクリアされません。同じゲームであることを再確認して続行してください。同じ他のアプリを少なくとも1秒以上3回以上確認した場合、正式に停止されます。不確実な状態が 3 秒続く場合は、「見込み客の検証が失敗し続けています」と実際の理由が表示されます。実際に一時停止した後も、手動で開始する必要があります。

ネイティブ scrcpy 4.0 で `--max-fps=120` を設定し、フレームレート = 120 をエンコードした実験では、クラッシュ前の約 3.95 秒間の有効セグメントは依然として約 61 FPS でした。 scrcpy ネイティブ プログラムは 0xC0000005 を除いて終了するため、この実験では長期的なフレーム レートの上限を証明できず、安定した代替バックエンドとして使用することもできません。現在、120 FPS を要求するためにフィル/重複フレームを使用せずに認証されたオリジナル ストリームを保持しています。

携帯電話の画面は 120Hz をサポートできますが、これは現在のゲーム画面、エンコード パス、キャプチャ パイプラインが 120 の新しい画面を提供することを意味するものではありません。 scrcpyのmax-fpsが上限設定となります。関連する実装については、[公式開発ドキュメント ](https://github.com/Genymobile/scrcpy/blob/master/doc/develop.md) を参照してください。これを本当に 2 倍にするには、ゲーム出力と安定した高フレーム レートのキャプチャ バックエンドを検証する必要があります。

## 角の丸いインターフェイス

新しいデスクトップ インターフェイスは PySide6 を使用します。ウィンドウの上部をドラッグして移動したり、右上隅を最小化したり閉じたりできます。カスタマイズ可能な角の丸いボタン、設定タブ、ステータス領域には、遷移アニメーションが表示されます。接続、観察、開始、一時停止、ADB 入力では、引き続き元のモバイル バックエンドが使用されます。設定またはボックスの選択を変更した後、適用するには再接続する必要があります。ウィンドウを閉じると、ウィンドウによって開始されたセッションが停止します。新しいバージョンは、古いバージョンで開いているウィンドウを自動的に引き継いだり、停止したりしません。

## 1.8.1 ウィンドウと完全なプレビュー

デスクトップ インターフェイスが開始されると、デフォルト サイズは利用可能な画面スペースに基づいて設定され、上限は 1180×900 です。手動調整範囲は 680×600 ～ 3840×2160 論理ピクセルですが、表示スケーリングと実際の画面の制限に応じて異なります。右上のボックスは、現在の画面の利用可能な領域 (上限を超えない範囲) までウィンドウを拡大し、もう一度押すと元に戻ります。右下隅をドラッグしてサイズを変更できます。

幅が760未満でウィンドウが縦長の場合、または幅が1200未満でアスペクト比が0.85未満の場合はトップダウン配置に変更され、開始/一時停止は下側に固定されます。残りの部分には、左列と右列が使用されます。狭い水平ウィンドウでは、X/Y 列が上下に配置されます。高さが 760 より低い場合、上部の領域が減ります。ウルトラワイド ウィンドウの主なコンテンツは、入力フィールドが過度に長くならないように、約 1680 論理ピクセル以内に保たれます。設定エリアは必要に応じてスクロールします。

プレビューでは、認識のために 336×598 で切り取られた画面の代わりに、携帯電話のストリーム全体が使用されます。外側のフレームは画像の縦横比に従って拡大縮小され、丸い角が適用されます。ディスプレイの解像度は依然として ADB ストリーミングによって制限されており、角が丸いため、角のピクセルがほとんど見えなくなります。プレビューをクリックするか、プレビューに焦点を当てて Enter/スペースバーを押すと、大きなライブ画面が開きます。プレビュー FPS は、描画される新しいフレームの実際の数に基づいて計算されます。ビューポートが隠れているか非表示になっている場合、ドロップする可能性があります。元の Tk インターフェイスには、認識注釈のプレビューがまだ保持されています。
