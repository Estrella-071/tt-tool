# 開發與驗證

[English](DEVELOPMENT.md) · 繁體中文 · [日本語](DEVELOPMENT.ja.md) · [한국어](DEVELOPMENT.ko.md)

本頁描述舊版模擬器與桌面開發流程。目前 Android 手機工具與 Windows 安裝程式請參閱 [ADB 手機開發](ADB.zh-TW.md)與 [Windows 安裝程式](INSTALLER.zh-TW.md)。

## 結構

- `main.py`：Tkinter介面、視窗選取範圍、設定與預覽開關。
- `fisher/vision.py`：影像歸一化、色彩與局部模板辨識。
- `fisher/controller.py`：釣魚階段、計數限制、結果重試和動作提交。
- `fisher/phase.py`：比例座標、三角波運動相位、雙向到達時間和同班去重。
- `fisher/runtime.py`：固定頻率截圖、可取消的獨立按鍵期限、控制指令和輸入協調。
- `fisher/scheduling.py`：截圖節奏與快速鍵邊緣。
- `fisher/speed.py`：參考速度、明確穩健校正和本機參數保存。
- `fisher/contact.py`：共享的有界延遲補償及歷史策略對照實現。
- `fisher/emulators.py`：雷電/MuMu標題篩選、手動選擇回退與選區歸屬校驗。
- `fisher/windows.py`：視窗座標、前台檢查和空格注入/釋放。
- `fisher/config.py`：配置校驗、遷移及原子保存。
- `fisher/packaging.py`：公開文件清單和ZIP完整性檢查。
- `desktop.py`、`build_windows.py`：選配便攜啟動與建置工具。

原始碼運行從`main.py`開始，正式介面統一選擇`phase`策略。歷史`contact`與`center`實現僅保留相容與迴歸對照；其測試明確固定原配置，不將歷史高頻樣例當成低頻策略驗證。

`ROOT`用於靜態資源，`DATA_ROOT`用於本機設定。新增公開檔案時同步`PUBLIC_FILES`，不得將本機設定、診斷資料或整個截圖目錄加入清單。

## 決策與輸入

控制器只提出動作，成功呼叫系統輸入後才`commit()`。相位策略的未來HIT進入唯一的待執行槽；每張新圖取代舊計劃，未知畫面或非判定階段取消計劃。循環在截圖間隔內也處理按鍵期限，不使用等待數秒的阻塞呼叫。靠近期限時暫緩截圖，先處理輸入。

相位計劃不能套用歷史策略的80/120毫秒幀齡限制；它的預測範圍由當前階段和下一次觀測約束。 F9、失焦、視窗變更和退出仍取消輸入。輸入後保留運動相位；同班鎖定在離開目標後解除，目標變更可啟動下一輪。

結果頁的record和claim樣式共用一段等待/重試流程。首次確認後等待，後續約每秒重試；未確認或離開結果頁停止關閉動作。不可因為綠色按鈕就把初始釣魚介面當作開心收下。收下按鈕以白色文字遮罩匹配，快取0.90～1.15倍的有限尺寸模板；只在綠色區域、暗背景和標題確認後執行，保持原有局部搜尋位置與最低0.72閾值。

`TRIAL_BUILD=False`為正式構建，不建立軌跡記錄器或會話日誌，不在暫停時匯出ZIP。歷史診斷模組只作為明確開發工具和回歸依賴保留。手動回放與測試輸出不屬於正常釣魚運行路徑。

時序演算法與邊界見[演算法說明](ALGORITHM.zh-TW.md)。目前模型假設勻速，不把長時間遊戲停頓當作已解決問題；低頻截圖下不應宣稱任意方向和變速都可唯一推斷。

## 驗證

```bash
python selfcheck.py
python replay.py
python build_release.py
```

自檢不發送系統按鍵。 `test_phase.py`包含模擬完整Runtime循環：分別以100毫秒和500毫秒採樣，在兩次截圖之間執行HIT；驗證左右折返、窄條、多輪目標、歸一化縮放、暫停/失焦/未知/尺寸變化取消，以及校準不加密截圖、不產生自動運行資料。舊策略、結算、截圖預算、快速鍵、輸入釋放、隱私及打包邊界繼續回歸。

測試素材使用必要的局部遊戲控制與脫敏框選範例。合成軌跡與錄影重播無法證明實際遊戲成功率，仍應區別離線檢查與Windows原生視窗、DPI、多螢幕和真實模擬器驗證。

設定版本7首次升級時開啟連續釣魚，將舊預設採樣間隔30改為6，保留其他自訂採樣值及快速鍵、等待等設定。新版已儲存的選擇不再被預設值覆蓋；舊選取範圍只在歸屬、標題和尺寸一致時重複使用。顯式校準開關只對本次監測有效。速度文件僅允許比例與統計字段，不保存原始軌跡或視窗資訊。
