# Windows 설치가 필요 없는 휴대용 버전

[English](WINDOWS.md) · [繁體中文](WINDOWS.zh-TW.md) · [日本語](WINDOWS.ja.md) · 한국어

> 이 기술 문서에는 이전 버전과 측정 기록이 포함되어 있습니다. 현재 설치 방법과 지원 기능은 [기본 안내서](../README.ko.md)를 참고하세요.

## 일반 사용자

프로젝트의 GitHub 릴리스에서 `tt-tool-emulator-版本号-Windows-x64.zip`를 선택하고 압축을 완전히 푼 다음 `启动钓鱼助手.bat`를 두 번 클릭합니다. 다운로드 페이지에서 해당 버전을 이미 사용할 수 있는지 여부는 프로젝트의 실제 릴리스에 따라 달라집니다. 휴대용 패키지 대신 GitHub에서 자동으로 생성된 소스 코드 ZIP을 다운로드하지 마세요.

64비트 Windows 10/11에 적용됩니다. 패키지에는 독립적인 CPython, Tcl/Tk, NumPy, OpenCV, Pillow 및 MSS가 함께 제공됩니다. Python, Anaconda, PyCharm을 설치하거나 추가 pip를 실행할 필요가 없으며 처음 시작할 때 구성 요소를 다운로드할 필요가 없습니다. LDPlayer 또는 MuMu 시뮬레이터와 게임은 여전히 ​​직접 준비해야 합니다. 이 프로그램은 시스템 Python, 레지스트리 또는 PATH를 수정하지 않습니다.

루트 디렉터리에 있는 `app/`는 전체 프로젝트 소스 코드와 리소스를 저장하고, `runtime/`는 독립적인 실행 환경을 저장하며, `data/`는 실행 후 로컬 구성, 로그, 스크린샷 및 비디오를 저장합니다. 패키지 인터프리터의 격리 모드를 사용하려면 해당 항목을 두 번 클릭하고, 사용자가 설치한 Python 패키지 및 PYTHONPATH를 읽지 마십시오.

현재 계정이 쓸 수 있는 위치에 압축을 푼다. 압축된 패키지 미리보기 창, 읽기 전용 디스크 또는 쓰기 위해 높은 권한이 필요한 시스템 디렉터리에 배치하지 마십시오. 동일한 데이터 디렉터리를 반복적으로 시작하면 이미 열려 있는 창으로 전환하라는 메시지가 표시됩니다. 서로 다른 폴더에 있는 별도의 복사본은 동일한 에뮬레이터를 동시에 제어하는 ​​것을 피해야 합니다.

처음 사용하는 경우 공간 매핑을 설정하고, 창을 선택하고, 전체 게임 영역의 프레임을 설정하고, 시작 버튼이나 단축키를 통해 낚시를 시작해야 합니다. 작동 단계는 [README](../README.ko.md)를 참조하세요.

## 업데이트 및 문제 해결

- 업데이트: 먼저 이전 버전을 종료하고 새 패키지를 새 폴더에 추출합니다. 이전 디렉토리 백업을 유지하십시오. 설정을 상속해야 하는 경우 이전 `data/`의 `config.json` 및 `speed_profile.json`만 새 패키지의 `data/`로 복사하세요. 존재하지 않는 파일을 만들 필요가 없습니다. 소스 버전에서 마이그레이션하는 경우 프로젝트 루트 디렉터리에 이 두 파일을 복사합니다. 과거 스크린샷과 비디오는 이전 디렉토리에 계속 보관될 수 있습니다.
- 열 수 없음: `检查运行环境.bat`를 두 번 클릭하여 표시된 오류를 유지합니다. 시작 오류는 `data/logs/startup.log`에 기록됩니다. 확인되지 않은 오류 로그를 노출하지 마세요.
- 파일이 가로채거나 누락되었습니다. 프로젝트 릴리스 페이지에서 가져온 것인지, 확인 값이 일치하는지 확인한 후 시스템 프롬프트를 따르세요. 일상적인 단계로 보안 소프트웨어를 끄지 마십시오.
- 일관성 없는 권한: 에뮬레이터가 관리자로 실행되는 경우에만 어시스턴트가 동일한 권한으로 실행되는 것으로 간주됩니다.
- 공유: 구축한 원본 ZIP을 게시하고, 이미 사용한 휴대용 디렉터리를 다시 압축하지 마세요.

## 유지관리자가 재생성됩니다.

웨어하우스 루트 디렉터리에서 실행:

```bash
python build_windows.py
```

빌드 항목에는 Python 3.10 이상의 표준 라이브러리만 필요합니다. 첫 번째 빌드에는 인터넷 연결이 필요하며 고정 목록에서 운영 환경 및 Windows 종속성을 다운로드하고 SHA-256을 하나씩 확인합니다. `.build-cache/`의 파일은 나중에 재사용할 수 있습니다. 빌드는 기본 `config.json`를 읽지 않거나 로그, 스크린샷 또는 비디오를 완제품으로 가져오지 않습니다.

출력은 `dist/tt-tool-emulator-版本号-Windows-x64.zip`에 있습니다. Windows 호스트에서 구축하면 패키지 해석기를 사용하여 Tk, ImageTk, 이미지 템플릿, 비디오 코덱 및 디스플레이 인터페이스를 확인합니다. 이 검사에서는 스크린샷을 찍거나 키 입력을 보내지 않습니다. 동일한 이식 가능한 패키지를 다른 운영 체제에서 조합할 수 있지만 바이너리 구조 및 파일 무결성 검사는 Windows 런타임 확인과 동일하지 않습니다. 게시하기 전에 Windows에서 인터페이스, 프레임 선택, 일시 중지 및 실제 시뮬레이터 작동을 확인해야 합니다.

소스 코드를 GitHub에 업로드한 후 **Actions → Windows portable → Run workflow**를 입력할 수도 있습니다. 워크플로는 Windows 시스템에서 구축 및 확인되며, 성공 시 다운로드 가능한 빌드 제품이 제공됩니다. 다운로드 후 GitHub 릴리스에 휴대용 ZIP을 수동으로 추가하세요. 워크플로우는 릴리스를 자동으로 릴리스하지 않습니다. 웨어하우스에는 `.github/workflows/windows-portable.yml`가 포함되어야 하며 점으로 시작하는 디렉터리를 놓치지 마세요.

`packaging/windows-runtime.lock.json` 고정 종속성 버전, 소스 및 해시. 종속성을 업데이트할 때 Windows x64/Python 3.12 호환성 및 라이선스도 확인하고 목록을 업데이트하기 전에 실제 다운로드를 확인해야 합니다. 버전 문자열만 변경하지 마세요. 현재 잠긴 패키지에는 휠용 추가 `.data` 설치 디렉터리가 없습니다. 이러한 종속성을 추가하려면 먼저 빌드 규칙을 확장하고 테스트해야 합니다.

이 프로젝트는 독립적인 실행 환경 디렉터리를 사용하여 설치가 필요 없으며 사용자 컴퓨터에서 단일 EXE 파일의 임시 압축을 풀 필요가 없습니다. 포털, 앱, 런타임은 항상 함께 배포하세요. 소스 코드는 명시적 파일 매니페스트에서 생성됩니다. 타사 바이너리는 업스트림 라이센스를 유지하며 버전과 다운로드 소스는 `DEPENDENCIES.json` 패키지에 기록됩니다.
